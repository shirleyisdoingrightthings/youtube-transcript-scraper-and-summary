# 发布格式统一规范（Publication Format · 跨形态）

> **适用范围：全部产物形态**——图文精读（模式 A）、对话体逐字稿（模式 B）、观察 / 观点稿（模式 C）、单人演讲实录。
> **本文件是这些约定的唯一来源。** 各形态 skill 只写自己特有的部分，排版与共有区块一律以本文件为准；如有冲突，以本文件为准，并回头修掉那个 skill。
> 定型自 Notion 范本《Claude Code 工程负责人 Fiona Fung：如何打造全世界最 AI Native 的工程团队?》，经用户确认为跨形态通用。

## 一、共有区块与顺序

每一篇成品，无论哪种形态，都由「共有壳」+「形态主体」构成。共有壳的顺序不可调换。

> **现行模板（2026-10-13 起）以 Notion 发稿版《1 万个 Agent 之后，我们仍不知道它们是否对齐》（Noam Brown 篇）为准**，取代此前定型自 Fiona Fung 篇的旧壳（开篇金句出现三次、导语、`# 核心观点` 在嘉宾背景之后、`# 写在最后` 每篇必出）以及 2026-09-12 的「履历叙事 + 编号判断清单」开头模板。旧壳见 git 历史，不再作为现行规则。
> **来源信息不进成品、也不另行留存**（2026-09-24 取消「本文来源」区块；2026-10-13 用户进一步明确：不写交接文档、不建校核子页、不建 sources.md，直接删掉）。读者可见的**图注**照写来源、口径与日期，不受此条影响。

| 位置 | 区块 | 说明 |
|---|---|---|
| 开头 | **题记**（blockquote） | 一句编者概括：这期是谁、谈了什么（例：「从多 Agent 协作、递归自我改进到思维链监控，Noam Brown 谈能力跃迁与安全边界。」）。**只出现一次**，不要求是嘉宾原话 |
| | **署名行** | `👩 编译：Shirley` / `🧑‍🎨 排版：NCon`，全角冒号，两行紧挨、中间不空行（上传后是同一个块） |
| | **品牌图** | 十字路口品牌图，初稿写 `🖼️ [图片占位：十字路口品牌图]`，用户排版时放 |
| | **编者按** | `**十字路口编者按：**` 起头，两段，见下文 |
| | `# 核心看点` | **无序列表**，每条「**一句加粗判断句。**一到两句展开」，条数按主题定（发稿版 8 条） |
| | `# 嘉宾背景` | 标题下空块，接一个 `💡` callout，见下文 |
| | **节目缩略图** | `![](https://img.youtube.com/vi/<video_id>/maxresdefault.jpg)` |
| 中段 | **形态主体** | 各形态自有：逐字稿走对话章节、图文精读走重构正文，等等 |
| 结尾 | **不设固定结尾区块** | 正文最后一轮对话（或最后一节）即结束；逐字稿不写「写在最后」；图文精读可按需写（见 `illustrated_deepdive.md`） |

> **callout 的写法**：本地 md 写成以 `> 💡 ` 开头的一行（如 `> 💡 Josh Woodward｜……`），`notion_upload.py` 会转成 💡 callout 块（`CALLOUT_ICONS`）。

### 生成顺序（强制 · 不只适用于精修，初稿同样按此）

**正文 → 核心看点 → 编者按 + 嘉宾背景 → 题记与标题。**

理由：核心看点是从正文里提炼的，正文没定就提炼不准；编者按要说清「这场对话追问的是什么」，得先知道正文与核心看点最后长什么样。**倒着做必然返工**，而且会出现核心看点覆盖不到后半场、编者按承诺了正文没兑现的东西这类错。题记与标题永远最后做。

### 嘉宾背景（`# 嘉宾背景`）

一个 `💡` callout，以 `姓名｜` 开头（全角竖线），**一段、两三句**，像简历一样克制：学历（如有）、与本期话题相关的代表工作、现职。发稿版范例：「Noam Brown｜毕业于罗格斯大学，获卡内基梅隆大学计算机科学博士学位。此前参与开发扑克 AI Libratus、Pluribus，并参与 CICERO 等多 Agent 系统的研究。现为 OpenAI 研究科学家，参与 o1 等推理模型的研发……」

- **这一块不受字幕约束**：它不是转写的一部分，可以用视频外的公开信息；正文那条「不加入视频外内容」的红线约束的是转写忠实度，不适用于本区块。
- **必须核实**：先用节目官方简介与一手资料（本人主页 / LinkedIn / 公司官网），缺关键事实再 WebSearch；职位、战绩这类硬事实**至少两个独立来源**（互相转抄的不算）。核不到的一律不写；拿不准的标 `⚠️建议人工核对`。**出处不写进成品**（见上方「来源信息」）。
- **只写与本期话题相关、核实过的经历，不做人物吹捧**（2026-10-13 修订，取代旧的「往他凭什么牛那一面写」）。**参与不能写成主导，公司 / 团队的战绩不能挂成个人战绩，设备装机量不能写成用户数。**具体的数字和动作仍比头衔和形容词好，但每个数字都要核主体、口径与时间。
- **二手编译稿里的战绩不得直接引用**，必须回本人主页或权威报道核到，核不到标 `⏸️未核`。
- **不承担「这篇为什么值得读」**，那是编者按的活。

### 编者按（`**十字路口编者按：**`）

紧跟品牌图，固定两段：

1. **第一段 · 新闻钩子**：一两句可核实的当下事实，带具体数字或事件（发稿版：「过去一个月，约 1 万个 Agent 并行工作 88 小时，产出了纳维–斯托克斯方程的候选证明；而另一场评估则显示……」）。这里的行业事实同样要 WebSearch 核实，但出处不进成品。
2. **第二段 · 本期追问**：「在这期与 <嘉宾身份 + 姓名> 的对谈中，<主持人> 从 A 谈到 B，最终追问一个更根本的问题：**<加粗的核心问题>**」。核心问题必须是这场对话真的在追问的，不得替嘉宾下结论。

- 不要写「这期视频讲了 X、Y、Z」，那是核心看点的工作；不复述履历。
- 可用「别人……而他……」的对比句式点出嘉宾的独特立场，但必须是嘉宾在正文里真说过的。

### 嘉宾背景与编者按：零重叠（强制）

这两块最容易撞车——都想讲「他是谁、他多厉害」。分工必须干净：

| | 嘉宾背景 | 编者按 |
|---|---|---|
| 回答什么 | **他是谁、凭什么** | **这篇为什么现在值得读** |
| 装什么 | 履历、战绩、过往判断记录 | 行业当下 + 这场对话的独特分量 + 本篇主线 |
| 不许装 | 本篇讲了什么、为什么值得读 | 复述履历与代表作 |

**自检方法**：把两段里的**专有事实**（公司名、代表作、可量化战绩、关键年份事件）各列一份，**两份清单不应有交集**。有交集就是重叠了，从编者按里删，履历只在嘉宾背景出现。

- 比的是**同一个事实**，不是同一个数字。编者按写「数据截至 2026 年上半年」、嘉宾背景写「2026 年 2 月出版」，年份相同但事实不同，**不算重叠**；只按数字比会误报。
- **典型的真重叠**是「提前喊过」那类记录被写两遍。正确分工：**编者按只下判断、不带证据**（「上一次他这样开口，是在上一轮估值调整之前」），**嘉宾背景供全证据**（哪一年、在哪说的、写了什么、后来兑现没有）。

### 三块的篇幅上限（强制）

这三块是读者最先看到的内容，**必须准确、且不能啰嗦**：

- **嘉宾背景**：**一段，两三句**。
- **编者按**：**两段，合计不超过 5 句**。
- **核心看点**：每条「一句加粗判断句 + 一到两句展开」，展开部分**不得复述判断句**。

**这三块尤其要清空转折废话**：「这句话不是修辞，而是……」「真正的分量不在 A，而在 B」「这不是 X，是 Y」这类句式，读起来像在铺垫，实际不传递任何信息，删掉之后意思不变就是废话。

### 编者按可用官方简介，但要去重（2026-09-22 起）

`fetch_transcript.py` 的输出 JSON 现带 `description` 字段（YouTube 官方视频简介，videoDetails.shortDescription），抓不到时为 `None`。生成编者按时可以直接用它：

- **官方简介写得完整、克制时，整段或裁剪后照用即可**，不必再自己编一段编者按——这是主持人/节目方自己写的路标，本就没有编者判断混进去的风险。
- **用之前必须与嘉宾背景、核心看点逐句去重**：官方简介常常自带履历（"XX 公司创始人""曾在 XX 工作"）或战绩数字，这些一旦嘉宾背景里已经写了，编者按里就删掉，只留官方简介里**嘉宾背景没覆盖到的部分**（通常是"这期聊了什么话题"）。判据同上文「嘉宾背景与编者按：零重叠」。
- **官方简介本身有硬伤或过度营销化措辞时不必照搬**，那种情况仍按老办法自己写编者按。
- 这条只解决"要不要写编者按"，不改变本文件其余规则（篇幅、零重叠自检等一律照旧适用）。

### 开场概念钩子段（按需使用，不是每篇都要加）

若正文里嘉宾自己讲过一个**能当标题钩子的命名概念**（例如他自己造的词、或反复提到的自创说法），标题用了这个钩子时，开场**可以**加一小段解开它的意思——但这**不是强制的第四种前置区块**，多数稿子不需要：

- 先看官方简介（见上条）或开头模板的核心看点里，**这个概念是否已经被自然带到、说明清楚了**；已经够用就不用再加一段。
- 只有当标题的钩子悬念在编者按 / 核心看点里完全没被兑现、读者会读到中途才反应过来"标题说的是什么"时，才值得单独加这一小段解释；加的话不起标题、直接紧跟嘉宾背景或编者按，控制在两三句。
- 判断加不加的标准是"读者读完开头能不能对上标题"，不是"这篇有没有一个新概念"——多数篇目靠编者按和核心看点已经够用。

### 核心看点的三项回验（强制 · 写完每条后立刻做）

**核心看点是全篇硬伤密度最高的地方**，因为它是"把一大段正文压成一句判断句"——压缩过程会系统性地丢掉三样东西。每条写完后，**须回正文与字幕各验一次**：

1. **限定语有没有被压掉**：嘉宾说的是「我不确定」「很难说」「这取决于」「目前看起来」，压缩后不得变成断言。**把嘉宾拒绝下的判断替他下了，等同硬伤**——这和「删减红线」第 4 条是同一类错，只是发生在压缩环节而不是删减环节。
2. **数量级与单位有没有跟正文对齐**：正文译对、核心观点压缩时挂错量级，是高发且最难自查的一类（读起来完全通顺）。凡出现数字，一律回字幕原句核对，不得凭正文的印象改写。
3. **「迹象 / 早期信号 / 有希望」有没有被写成既成事实**：原话是 `signs of` / `early` / `promising` 时，压缩后不得抹掉这层修饰。这类词是研究者对自己结果的克制表述，抹掉即拔高。

> 实例教训：某期演讲实录的 Agent Council 清出 4 处必改硬伤，**全部落在导读层、正文本体零硬伤**——核心观点把 `far more useful when...`（程度比较）写成"只有…才真正有用"（排他条件）、把 `I'm not sure we'll have...` 写成"不会有"、把 `strong signs of compositional generalization` 写成"组合泛化出现了"、把"一百万条轨迹对应 700 个机器人日"错挂成"几百万"（差 3–10 倍）。四处正文都是对的，错全出在压缩那一步。

**怎么验（强制 · 不得只据中文正文提炼）**：回验的依据是**字幕原句**，不是你自己刚写好的中文正文。做法是——对每一条核心观点、每一个章节标题、导语里的每一句判断，**回到它所概括的那段字幕，把原句读一遍再定稿**。只对着中文正文提炼，等于让压缩误差在同一条链路上传递两次：正文译对了，压缩层照样会走样，而此时你已经没有参照物能发现它。

**适用范围是整个压缩层**：`# 核心看点`、**每一个章节标题**、编者按、题记。这几处的共同特征是"把一大段压成一句"，硬伤密度远高于正文本体，且**读起来通顺，自查发现不了**。

> 实例教训之二：某期逐字稿的 Agent Council 清出 4 处必改，**同样全部落在压缩层、正文本体逐段核完干净**——章节标题把 `expanding your thinking of what's possible`（想象力）写成"野心"，**恰好反了嘉宾的论点**（她认为野心是能抬的、想象力才是瓶颈）；核心观点把 `don't simply… but`（递进）写成"不是…而是"（排他）；导语写"几乎没人愿意公开说"，而嘉宾原话是 `I'm sure many people have talked about this`，**被本篇正文当场证伪**；`equally wrong` 被加码成"一模一样致命"。这几处的字幕原句**正文全部译对了**，错全在提炼那一步。

**结尾**：不设「写在最后」（2026-10-13 起）。正文最后一轮对话即结束，不为模板再总结一次。

**来源信息**：不进成品、不另行留存（见本节开头）。

## 二、排版（全形态硬性）

- **章节标题单级：全篇只用 `#`（H1），不设 `##` 子标题**（2026-09-22 用户口径，**推翻 2026-09-21 定的「H1+H2 两级」方案**——两级读起来太碎）。参考 8-10 章、上限 11 章。标题要具体、点出本章讲什么：可以是判断句、有信息量的问句或描述句（发稿版：「多 Agent 会怎样重塑公司？」「Hugging Face 事件：协作能力如何变成对齐风险」），也可以直接摘正文里嘉宾的强 quote；**不得把嘉宾没下结论的问题写成结论**。逐字稿的具体写法见 `dialogue_transcript.md`「章节标题」。
- **标题文字一律不加粗**：`#` / `##` 在 Notion 里本身就是粗体，标题里再包 `**…**` 是多余的格式（用户 2026-09-11 口径）。
- **正文加粗规范（2026-09-24 用户口径，2026-09-28 修订）**：只加粗两类句子——**能被直接 quote 的金句**，或**信息量很足的一句**（关键数字、核心机制、一手披露）；每章 1-3 处（长章可略多），整篇不铺满；一处不超过约 40 字，用户点名要加粗的类比等例外；不加粗普通因果句、术语名、引子句、问句。**加粗与章节标题脱钩：章节标题已经摘了某句，正文那句就不必再加粗**（2026-09-28 推翻旧的「标题即出处、正文保留加粗」）；判断只看这句本身是不是金句或料足。用户亲手加的加粗视为有意决定，Agent 不擅自取消。
- **全篇禁用 `---` 分割线**，区块之间靠 `#` 标题分隔。
- **不写 YAML Frontmatter、不打 Obsidian 双链 `[[ ]]`**（历史残留，Notion 端不消费）。
- **媒体占位符**：`🖼️ [图片占位：…]` / `🎞️ [GIF 占位：…]` / `📊 [图表占位：…｜图注须标注…]`。一篇 5–12 个，不泛滥。

### 数字、单位与术语写法（强制 · 2026-09-21 用户口径）

- **计数与度量一律用阿拉伯数字**：8 块 GPU、4-5 倍、8 倍、8,000 Token、20 万 Token、第 100001 个 Token、1 万亿参数、3-6 个月、70%-80%、19%-21%。**只换写法，值不能变**（属「按字面保留」的保护区）。
- **1,000 及以上用千分位逗号**（2026-10-13，按 Noam 发稿版）：1,300 亿、2,000 个、4,000 年；年份、型号、编号、页码不加（2026 年、GPT-5.6、第 100001 个）。
- **不转的**：序数与固定说法（"第一""其一""一方面""一个人""一样"）、成语与虚指（"一两分钟""好几年"这类本就模糊的说法保持原样）。
- **单位用符号**：21 PB/s、10 TB/s、288 GB、500 MB、50 GB，数字与单位之间空一格；不写"拍字节""太字节""吉字节"。**电力单位例外（2026-09-23 用户口径）**：兆瓦、吉瓦首现写成「兆瓦（MW）」「吉瓦（GW）」，此后全篇只写中文「兆瓦 / 吉瓦」，不再用 MW / GW。
- **区间用半角连字符 `-`**：3-6，不写"三到六""3 到 6"，也不用破折号（2026-09-24 用户定）。
- **算力单位**：FLOPS 是每秒运算次数（速率），FLOPs 是运算总量。芯片的算力、每美元算力一律 FLOPS（TFLOPS / PFLOPS）；只有讲一次任务的总运算量时才用 FLOPs。见 `glossary.md`。
- **首现的新概念或嘉宾自造词，中文后括注英文原词**：每美元算力（compute per dollar）、工作量证明（proof of work）、品味（taste）、拾荒者策略（scavenger strategy）。
- **术语补注只给「读者不看注就读不懂」的首现词**（如 MoE（混合专家）、RoPE、SRAM）。中文科技读者已惯用的英文词（NeoCloud、harness、human in the loop、Agent、Token 等）保持英文、不加括注；一旦保持英文就全篇保持英文，不在别处又译成中文（2026-09-24 用户口径）。
- **中英文名词前后统一**：同一公司 / 产品 / 术语全篇一种写法（英伟达不与 NVIDIA 混用，KV cache 不与 KV Cache 混用，Scaling Law 大小写固定）；同一个英文比喻全篇一种译法（如 happy path 只译一种）。定稿前用 grep 扫一遍，不靠目测。

### 空行规则（强制 · 直接决定 Notion 里的分块与留白）

Markdown 的**单个空行**只是分块，到 Notion 不留痕；**连续两个空行**才会被 `notion_upload.py` 转成一个**空段落块**，也就是读者真正看得见的留白（文档首尾不落空块）。直接用 Notion MCP 改线上稿时，这个空块写作 `<empty-block/>`。据此：

- **每个 `#` / `##` 标题之下都要有一个空块**（md 里空两行），再接内容。`# 核心看点`、`# 嘉宾背景` 也一样，唯一例外是文档主标题。这条是用户 2026-09-11 定的，取代旧的「非正文标题只空一行」。
- **对话形态：说话人标签之前空两行**，标签与其发言之间空一行。效果是每一轮发言自成一块，相邻两轮之间有一个空块；同一个人的一轮发言可以有多个段落。
- **同一段落层级的相邻段之间空一行**。不空行会被合并成同一个段落块，在 Notion 里粘成一大坨。
- 空行最多连续两个，不要堆更多。

### 说话人标签（仅对话 / 访谈形态）

- 格式：**`emoji + 空格 + 姓名`，不加冒号、不加任何标点**，标签独占一行，内容从下一行开始。
- **emoji 固定约定**：主持人 `🎙️`、男性嘉宾 `👱‍♂️`、女性嘉宾 `👩`。同一人全篇不变。
- **称呼（2026-10-13，按 Noam 发稿版）**：主持人首次写 `🎙️ 主持人（Dwarkesh Patel）`，之后一律写 `🎙️ 主持人`；嘉宾每次都写全名（`👱‍♂️ Noam Brown`）。
- **不得凭姓名推断性别**。性别须有可核实的依据（本人公开自述、官方页面、节目方称呼）；无从判断时用中性的 `🎙️` 或 `👤`。
- 多位主持人若自动字幕无法区分，**统一标注为「主持人」并在交付汇报里说明**，不要凭猜分配。

### 两种插入物的分工

- **`>` 引用块**：金句、嘉宾引用的推文 / 数据、英文原句 + 中文翻译，以及未走并入协议时的外部素材「📎 延伸」块。
- **`💡` 单行**：**编者的提炼**，紧跟对应内容之后，一两句点破机制或反差。**逐字稿默认不用**（2026-10-13 起按 Noam 发稿版，正文只留对话）；图文精读可用（含「说人话」保底句）。发稿版里还用 `💡` callout 承载被压缩概括的主持人长段铺垫，那属于精修阶段由用户授权的选编，初稿不主动这么做。
- **对话形态里，编者不得在说话人发言中插入自己补的具体例子**——哪怕加括号注明"此例为编者补充"。想举例子，只能挪到 `💡` 提炼行或「写在最后」，不能出现在说话人标签下的发言正文里，那会让读者以为是嘉宾自己说的。
- **`📎 延伸` 引用块与表格，若跟在某个说话人发言中间，要挪到该小节末尾**——不要打断发言，也不要让编者补充读起来像嘉宾话里的一部分。挪动时确认锚点仍留在同一节内，不要跨节搬运。

## 三、去 AI 味（强制自检）

> 本节的模式清单部分借鉴自两个 MIT 许可的开源 skill：[MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua)（句式库与严重度分级）与 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)（译自维基百科「AI 写作特征」）。**只借模式判据，不借它们的改写哲学**——原因见本节末尾「两条反向条款」。

### 先保护，再改写（强制 · 动笔前先做）

去 AI 味本身就是**改写动作**，是全流程里最容易伤到忠实度的一步。历史上最高发的硬伤全出在这里：正文都译对了，是润色 / 压缩那一步把限定语弄没的（`Probably` 漏掉、`frequently` 弱化成「甚至可能」、`I certainly doubt it` 写成既成事实）。因此**动笔前先划保护区**，分两种强度：

| 保护强度 | 内容 | 规则 |
|---|---|---|
| **按字面保留** | 数值、百分比、时间、日期、版本号、区间、单位；人名 / 公司 / 产品 / 模型等专名；标识符与代码；引用原话 | 一字不改。不四舍五入，不把精确说法改成模糊说法 |
| **按含义保留** | 状态与完成度、条件与前提、比较关系、因果方向、嘉宾的让步与限定 | 允许清理包装措辞，但**语义强度不得变**。「大概可以」不能变成「可以」，「他表示怀疑」不能变成「确实如此」 |

改完**回读时逐类核对保护区是否还在**，这一步并入 Step 2.5。

- **尽量不用破折号 `——`**：破折号密集是最典型的 AI 痕迹。**例外**：对话被打断的半句可用 `——` 收尾。
- **少用「不是…而是…」**，一篇两三次就够。
- **包装词分三级处理，不要一刀切**（一刀切会误杀「然而」「正是」这类单用完全合理的词）：
  - **Tier 1 · 默认删改**：值得一提的是、不难看出、综上所述、换句话说、某种程度上、令人瞩目、难得地、赋能、助力、打造、抓手、闭环、颗粒度、深远影响、前所未有、拭目以待、保姆级。
  - **Tier 2 · 同段聚集才算**：然而、此外、与此同时、显著、有效、全面、持续、进一步、充分、恰恰、正是、无疑、可谓、堪称。**阈值**：短段落（<100 字）同段出现 2 个即标记；长段落（≥100 字）3 个才标记，2 个散落在不同位置可放行。处理时保留最贴切的一个，其余改写句式。
  - **Tier 3 · 只在明显过量时处理**：重要 / 关键 / 核心 / 提升。
- **禁用空转连接**：「首先 / 其次 / 最后」式机械罗列、「不仅…而且…」滥用、排比句轰炸。
- **禁用「元叙述＋冒号」句式（`他 X 了一句：内容`）**——这是最像 AI 写的一种结构，冒号前只是在**宣布"他说了话"**，不传递任何信息。典型：「他由此给出一个具体的设计取向：」「他把这个词拆得很具体：」「他把话留了一半：」「他补充了一个反直觉的观察：」「他还提了一句对照：」「他的通俗解释是：」「他说得很具体：」「Movva 的回答是：」。
  - **判定方法**：把冒号前那半句整个删掉，若句意不变，它就是废话。
  - **改法三选一**：① 直接删掉引导语，让内容自己开口；② 冒号改逗号或句号，把两半合成一句正常的话；③ 引导语确有信息时，把它改写成陈述而不是宣告（「他把这称为数据中心的规模不经济。」而非「他把这称为规模不经济：」）。
  - **合法的冒号只有三类**，不要误删：引出**真正的问句**（「主持人问他：有哪些看法会让朋友觉得他长了三个脑袋？」）、引出**清单或枚举**（「先把供应链瓶颈说清楚：晶圆产能、HBM 产能、先进封装，以及电力」）、引出**逐字引语**。
  - **对话形态同样适用（2026-09-29 用户口径，推翻「说话人嘴里的冒号句要保留」）**：译文里的「XXX：XXX」多半是译者加的结构，不是说话人的口语，AI 味一样重。说话人发言里也尽量改成句号、逗号或调整语序（「你会看到一个非常清晰的规律：模型想得越久…」→「你会看到非常清晰的规律，模型想得越久，答得越好」）；只保留上面三类合法冒号，尤其是引出逐字引语的（「一个 agent 说：“…”」）。
- **禁用装饰性细节（红线 · 转录类形态尤其）**：用具体的时间、天气、动作、物件伪造现场感（「凌晨三点，办公室只剩他一个人，桌上的咖啡早就凉了」）。**判定只看一条：该细节有没有来源**（原始素材里有、可核验）。没有来源就删，不论它是否影响后文（2026-10-13 修订：旧判据要求「删后事实与因果不变」同时成立，会放过那些改变了因果的编造细节）。我们已有的红线管的是「不得加入视频外的**判断**」，这条补的是「不得加入视频外的**细节**」——伪造画面比伪造判断隐蔽得多。
- **禁用动词名词化**：把动作压成「空动词 + 抽象名词」，句子变长、信息没变。信号词是 `进行 / 实现 / 完成 / 开展 / 起到 / 具有 / 加以 / 予以` 后面跟一个动名词。❌「对流程进行了优化」「团队进行了讨论」→ ✅「优化了流程」「团队讨论过」。**改写只换句式，不得新增素材里没有的动作、频率或数字**（旧示例「一天能多处理 20 单」凭空加了数字，已于 2026-10-13 删除）。**这是「研报腔」最主要的成因**，也是可以机器筛的。
- **禁用虚假主语**：给无生命的事物安上人类动作（赋能、助力、驱动、加持、构筑、铸就）。**例外**：技术描述里的非人主语是合理的（「网关返回 504」「缓存过期」「控制平面把负载迁走」），不要改。
- **禁用同义词躲避**：同一个东西在相邻几句里被迫换三种说法，而且一次比一次抽象。人写东西不怕重复关键词。❌ 同一个「推理服务商」在相邻几句里被换成「推理平台」「算力供应方」→ 全篇锁一个写法。**先判断是不是同一个概念**：开放权重（open-weight）与开源（open source）是不同的许可概念，原文区分时译文也要区分，那不算同义词躲避。**注意这与 Step 2.5 的「术语统一」不是一回事**：那条要求译法对齐 `glossary.md`，这条抓的是**为了避免重复而故意换词**。
- **禁用借喻场混用**：同一段里从多套不相干的比喻系统借词（道路竞赛、战争攻防、建筑灾害、温度、生物…）。比喻密度高的稿子尤其要查——一段里既「押注」又「拧螺丝」又「涨潮」，读者的画面会散。
- **节奏自检**：`check_transcript_edit.py` 会打印句长变异系数与「连续三句长度相近」的处数（对任何形态都跑，包括无时间戳的图文精读）。变异系数偏低说明读起来平、没有呼吸感，**改法是合并或拆分句子制造长短交替，不是重写全文**。参考基线：本项目已定稿的两篇为 0.50 / 0.58。**对话形态的说话人发言不必强行打断**，那是真实语速。
- **同一种编者注不要重复超过两次**：「这是他的判断，不是行业现状」这类免责句，全篇最多留两处最必要的，其余把限定直接写进句子里。
- **原则**：用具体事实代替形容词；能删的过渡句直接删；嘉宾原话可口语，编辑旁白要书面克制。

### 两条反向条款（借鉴外部 skill 时必须挡住的坑）

通用「去 AI 味 / humanizer」工具是为**自由写作**设计的，有两条与本工作流**方向相反**，照搬会当场制造忠实度硬伤：

1. **不要「注入灵魂」。** 那类工具会要求加第一人称、加个人观点、允许跑题和「半成型的想法」，把「实验产生了有趣的结果」改写成「我真的不知道该怎么看待这件事……」。**本工作流的正文不得加入素材之外的判断**；逐字稿的编者声音只能进 1–3 处 `💡` 与「写在最后」。
2. **不要清「过度限定」。** 那类工具会教你把「可能 / 或许 / 大概 / 被认为」删干净。**嘉宾的让步与限定语必须原样保留**（「我不确定」「很难说」「那取决于」「Probably」），那是忠实不是啰嗦。真正该删的是**编者自己**堆的限定（「可以潜在地可能被认为」），两者不要混。

## 四、各形态如何接入

| 形态 | 形态主体 | 与共有壳的衔接 |
|---|---|---|
| **对话体逐字稿**（模式 B） | 按原始时间线的对话章节，每节一个 `#` 标题 | 完全按共有壳。细则见 `dialogue_transcript.md` |
| **图文精读**（模式 A） | 按主题重构的叙事章节 | 共有壳之外**保留模式 A 专有的**：摘要钩子、封面 Recraft Prompt、编者按末尾的「📍 本文路线」路线条、正文中的一句话路标与「说人话」保底句、系列回链。`# 写在最后` 按需写；其余共有壳与逐字稿一致。细则见 `illustrated_deepdive.md` |
| **单人演讲实录** | 按幻灯片锚定的第一人称分节 | 无说话人标签；其余全按共有壳 |
| **观察 / 观点稿**（模式 C） | 中心判断线 + 分判断 | 共有壳照用；「嘉宾背景」按信源情况可省。细则见 `observation_commentary.md` |

**共有壳的区块名以本文件为准**。历史稿件里的旧名（「开篇金句」「导语」「`# 核心观点`」「`# 写在最后`」等）不必回头改，但新稿一律用现行模板（题记 / 编者按 / `# 核心看点` / 无结尾区块）。
