# 图文精读稿生成规范（Illustrated Deep-Dive）

当执行模式 A（默认）时，把一期视频做成「可直接发公众号的图文精读稿」，严格遵守本规范。
本规范是工作流的主力产物标准；另一种产物是对话体逐字稿（见 `dialogue_transcript.md`）。

## 核心定位

图文精读稿 = 观点提炼（深度重构，不逐句还原）+ 完整图文（叙事章节 + 密集媒体占位）+ 公众号发布全套要素（标题 / 摘要 / 封面 Prompt）。
产出目标：一篇打开即可排版发布、且每一句都经过原始字幕核校的高密度图文长文。

**共同底线**：所有事实、数字、专有名词、因果逻辑必须能在 `transcript.json` 中找到出处。定稿前必须执行 CLAUDE.md 的 **Step 2.5 对照字幕核校**。

---

## 输出结构

> **共有壳与全部排版约定见 `skills/publication_format.md`，那里是唯一来源**——题记、署名行、品牌图、编者按、`# 核心看点`（无序列表）、`# 嘉宾背景`（💡 callout）、节目缩略图；以及 `#` 标题、禁 `---`、空行规则、`>` 与 `💡` 分工、媒体占位符、去 AI 味清单。本节只写模式 A 特有的部分。

**完整顺序（共有壳 + 模式 A 专有，按此排；2026-10-13 起共有壳与逐字稿一致）：**

1. 标题（含系列标记）
2. **摘要钩子**　🅰️ 模式 A 专有
3. **封面图 Recraft Prompt**　🅰️ 模式 A 专有
4. 题记 + 署名行 + 品牌图（共有壳）
5. **编者按**（共有壳）＋末尾 `📍 本文路线` 路线条　🅰️ 路线条为模式 A 专有
6. `# 核心看点`（共有壳）
7. `# 嘉宾背景`（共有壳，💡 callout）＋ 节目缩略图
8. **重构正文**（叙事章节，含减负装置）　🅰️ 模式 A 特有的主体
9. `# 写在最后`（**按需**：有正文与编者按之外的新判断才写）
10. （如有）下集预告 / 系列回链

> **2026-10-13 改动说明**：原「内容与价值概括 / 导语」改为共有壳的「编者按」，原强制双锚点里的「写在最后」改为按需；核心观点改名「核心看点」并移到嘉宾背景之前。历史稿件不必回头改。

### 1. 标题

- 一次生成 **5 个候选**，覆盖不同钩子类型，供用户挑选：
  1. 冲击 / 反共识型（名人 + 金额 + 争议，打开率最高）
  2. 金句型（点出核心主张）
  3. 悬念 / 对立型（"所有人 vs 他"）
  4. 设问 / 科普型（门槛低、稳）
  5. 干货 / 深度型（体现深度定位）
- 系列内容必须在标题末尾标注 `（上集）`/`（下集）` 或系列名。
- 给出推荐项 + 一句话理由（哪种调性选哪个）。

### 2. 摘要钩子

- 定位：公众号标题下方的摘要，**唯一 KPI 是"勾人点进去"，不是概括内容**。
- 要求：≤20 字优先；带悬念 / 冲突 / 利益相关，避免"目录式"罗列专业名词。
- 优先把读者拉进来（如"你正在用的 X"），从旁观者变利益相关者。
- 与标题分工互补、不重复：标题给"是谁 + 什么观点"，摘要"加注下重码"。

### 3. 封面图（两步流程 · Recraft 定风格 → Nano Banana 叠字调细节）

封面走两步，**模式 A / B 通用**（逐字稿也用这套，不必只用原片截图）。**最终成图必须 2048×1024、高清——这是硬性要求。**

**第一步 · Recraft AI 定背景与整体风格（出干净底图，不带文字）**
- 面板设置：`Style = Motion Blur｜Size = 2048×1024（2:1）`。
- 输出一段可直接复制的**英文 prompt**，**务必 `no text`**——AI 嵌字必糊，所有文字一律留到第二步叠加。
- **「十字路口」house style（默认调性）**：暗冷、电影感长曝光 / 动态模糊；teal-black 暗底 + 横向 amber / warm-white 光轨；冷调玻璃与空间纵深；warm amber 点缀；premium、minimal、克制留白。**顶部或中央留出干净暗区**给主题词。人物可有可无（要"一个 leader 对着 agent 面板"就放一个背影 + 几个虚化队友；要纯抽象就 `no people`）。
- 系列：同一系列共用 house 调性与构图母题，只改一个差异点区分集数。
- 可复用模板（把 `{概念}` 换成本期视觉概念）：
  > `A dark, cinematic {概念} in a bold motion-blur, long-exposure style. Teal-black moody scene with horizontal amber and warm-white light trails, cool glass-and-space depth, warm amber accents. Keep clean dark negative space at the top/center for a title to be added later. Premium, minimal, high-end tech-editorial mood. recraft v3, motion blur, 2048x1024. No text, no letters.`

**第二步 · Google AI Studio（Nano Banana 最新模型）叠主题词 + 调细节**
- **叠主题词**：把本期主题词（如 `Leading AI Native Teams`）放在**顶部或中央**，走 house 字体——**细体 / light-weight 干净无衬线（Helvetica Neue Light 类）、字距拉开、柔白 #F3F8F8 + 微光**，像发光招牌；暗底直接白字，浅底加淡阴影。
- **调细节（按需）**：把画面里的屏幕换成 **Claude Code 的 CUI / 终端界面**（深色终端 + 彩色代码行，可叠小号等宽 `Claude Code`）；加 **Claude logo（八角星标）**（顶部居中或角落）。
- **保真要求**：只叠字 / 改指定细节，不动其余画面；保持动态模糊与配色；**导出 2048×1024 高清**。

> 封面铁律：第一步 `no text`、第二步才叠字；字体走 house light-weight 细体；最终 **2048×1024 高清**。

### 4. 编者按与路线条

- **编者按按 `publication_format.md`「编者按」写**：两段，第一段新闻钩子（可核实的当下事实与数字），第二段本期追问（核心问题加粗）；只讲"事"，不复述履历。
- **严禁与"嘉宾背景"重复**：人物履历一律交给嘉宾背景。
- **结尾附「路线条」导航（模式 A 专有，长文必备）**：编者按末尾、进核心看点之前，放一个 `📍 本文路线：A → B → C → D → E` 的 callout（浅灰底、📍 图标，**不是标题**），用箭头串起各大章节关键词，给读者一张"全程地图"。
  - 关键词与正文大标题一一对应；末项用中性、不预设结果的词（如"成色几何""他在赌什么"，**不要写"赌局比分"这类预设输赢/过于抽象的词**）。
  - 系列内容上下集各自一条路线，约 5 站为宜，简洁优先。

### 5. 嘉宾背景

- **按 `publication_format.md`「嘉宾背景」写**：💡 callout，以 `姓名｜` 开头，一段两三句，只写与本期话题相关、核实过的经历（学历、代表工作、现职），不做人物吹捧；参与不能写成主导，公司战绩不能挂成个人战绩。
- 与编者按严格分工，零重复；所有履历必须公开可核实，不得编造；出处不写进成品。

### 6. 核心看点

- **格式按 `publication_format.md`**：`# 核心看点`，放在嘉宾背景之前，无序列表，每条「**一句加粗判断句。**一到两句展开」（2026-10-13 起取代旧的 `### 钩子标题` 写法）。
- **保留项**：默认保留本段。是否精简 / 弱化，由用户按稿件实际决定，**不擅自删除**。
- **按视频时长分档**：
  - 30–40 分钟视频 → 精简到约 **5 条**。
  - 1 小时左右视频 → **5–8 条**。
- **宁可聚类、不要罗列**（8 条零散 → 合并成链）。各条之间要构成**逻辑链**（判断 → 旧路为何不行 → 新路跑通 → 真正方案 → 终极结论），而非并列知识点。
- 编辑概括性的强断言（如"死路"）可用于标题 / 编者按；核心看点里若涉及，注意分寸，必要时回退到更贴原话的表述。

### 7. 重构正文（叙事章节）

- 按视频时间线推进，但**按主题重构**（不逐句照搬字幕）。
- **正文不再自行标注时间戳**：直接对照"原始字幕 + 逐字稿"重构内容即可，章节标题与正文中均不放 `[MM:SS]`。
- 章节标题：**全篇只用 `#`（全形态单级，见 `publication_format.md`）**，要叙事性 / 场景化，或写成有信息量的问句，禁用功能性标题（如"关于 X 的讨论"）。内容过长时拆成两章，不加 `##`。
  - 每个标题与其下内容必须精确对应，杜绝"挂羊头卖狗肉"。
- **媒体占位符**：在对应段落下方嵌入 `🖼️ [图片占位：…]` / `🎞️ [GIF 占位：…]`，对应原视频的关键截图 / 演示画面（用户据此放截图或 GIF）。一篇通常 8-15 个，不泛滥。
- 关键金句、定义用引用块 `>` 或 `💡 aside` 框承载。
- "下集预告"等过渡内容降级为引用块，不与内容大章并列 H1。

#### 长文减负装置（6000 字以上硬核稿必备）

长科普文准确不等于读得下去。以下三件套专治"太长、有门槛、读完不知所云"，总增字数不过两三百，却显著拉高完读率：

1. **路线图句**（开头·1 句）：正文第一个大标题之前加一句"行程预告 + 安全承诺"，告诉读者要被带去哪、会经过什么，并降低畏难情绪。
   - 例：「接下来这趟，我们会从一张"蛋糕幻灯片"出发，看 LeCun 如何一步步推到"世界模型"——**不需要任何技术背景，跟着走就行。**」
2. **一句话路标**（中途·2-3 处）：在关键转折的大标题下、正文首句之前，加一句"承上"的过渡，让读者随时知道身处逻辑链第几环。三处足够，不必每节都加（否则碎）。
   - 例：「联合嵌入看起来已经完美绕开了"模糊诅咒"——但它藏着一个能让整个方法失效的致命漏洞。」
   - 例：「前两层，JEPA 都赢得漂亮，但到了第三层，故事开始变得不一样了。」
3. **"说人话"保底句**（硬核段·按需）：全文门槛最高的技术段（矩阵、公式、架构拆解）末尾，加一句让看不懂细节的人也能拿到结论的话，用 `💡 callout` 跳出。
   - 例：「💡 **看不懂上面这些矩阵也没关系，一句话总结**：就是逼着每个神经元各管各的、别都学成一个样，模型既偷不了懒、又能学到真正有用的特征。」

> 此外，正文导航全局靠编者按末尾的「路线条」、局部靠这里的「一句话路标」，需要收尾时再用按需的「写在最后」，构成完整的"导览系统"。

### 写在最后（按需 · 2026-10-13 起）

- **不再强制**。只有当编辑有正文与编者按之外的**新判断**时才写，不为模板再总结一次。
- **写的话**：标题固定 `# 写在最后`；先给"两面"的诚实判断（亮眼的一面 + 清醒的一面），用具体事实；末尾留一个开放问题，把判断权交还读者；强断言要落在事实上，不预设输赢；不复述编者按与核心看点。
- **系列稿分工**：上集收"论点 / 立场" + 抛悬念给下集；下集收"论据 / 现状盘点" + 开放结局。

### 系列上下集处理规范

当一期内容拆成上 / 下集（或多篇系列）时：

- **嘉宾背景跨集完全一致**：同一段、一字不改，强化人物印象（不必每集换写法）。
- **承接句（上抛下接）**：上集结尾抛出的悬念，下集开头第一段必须用一句话"接住"（如"上集结尾我们留了一个问题：…这一集，他给了答案"）。形成"抛—接"闭环。
- **结构线索贯穿**：若正文用"第一层 / 第二层 / 第三层"这类层级线索，必须贯彻到底、不中途脱轨。
- **双向回链**：上集指向下集、下集回指上集；与对照系列（如其他嘉宾同题）互链。
- **路线条各集独立**：每集一条自己的路线条，不共用。

### 去 AI 味（强制自检）

定稿前扫一遍，删掉一眼就是"AI 写的"的词与句式。**目标是保持冷静、有判断力的编辑语感，不是改成大白话。**

- **尽量不用破折号（——）**：破折号密集是最典型的 AI 痕迹，用逗号、句号或分句替代。
- **禁用包装词**（举例，非穷举）：自洽优雅、中期比分、逆袭、难得地、罕见的、令人瞩目、值得一提的是、不难看出、综上所述、换句话说、某种程度上、在这个意义上。
- **禁用空转连接**："首先 / 其次 / 最后"式机械罗列、"不仅…而且…"滥用、排比句轰炸。
- **原则**：用**具体事实**代替形容词（"16 亿打赢 70 亿"胜过"成绩斐然"）；能删的过渡句直接删；引用原话可口语，但旁白叙述要书面克制。

## 对照字幕核校

定稿前必须执行 **CLAUDE.md → Step 2.5 对照字幕核校**（工作流核心，模式 A / B 通用）。
要点：逐板块核对事实 / 数字 / 专名 / 因果；**专名核对铁律**（外文名高风险，先查证、拿不准就标 `⚠️建议人工核对`、绝不臆造；五条判据见 `skills/proper_noun_check.md`）；区分必改硬伤与可选润色；对照 `glossary.md` 统一术语；每批给"✅无硬伤 / ⚠️N 处硬伤"总判定。详见 CLAUDE.md。

## 标题生成与文件命名

- 中文发布标题：一句主题，不强制 `嘉宾姓名｜` 前缀（与逐字稿一致，见 `publication_format.md`）；含 `/`、`:` 等非法字符替换为 `-` 或空格；不用下划线拼接。
- 文件名：`<生成的中文标题> - 图文精读.md`
- 存放：`output/<生成的中文标题>/`，与 `transcript.json` 同目录。
- 系列内容（上 / 下集）各自独立目录，但在导读区**双向回链**。

## 输出语言
- 全文简体中文；高共识词保留英文（Token、Agent、JEPA、GPU、API、Transformer…）；
- 公司 / 产品 / 项目代号保留英文原名；新概念首次出现时括注中文解释。

## 面向发布的多轮精修流程（交付初稿之后）

初稿交付用户、用户听完原片提意见后，进入**协作精修**。**固定按以下顺序改，每处改动都对照字幕核校（Step 2.5 精神）：**

1. **外部素材并入**（在正文层处理，因为只有正文才有结构调整）。
2. **正文**：叙事章节 重构 / 合并 / 删减 / 调序，连带调整 路线条 / 减负装置 / 媒体占位。
3. **非正文**，子顺序固定为：**核心看点 → 编者按（含路线条）→ 嘉宾背景 → 写在最后（如有）**（与 `publication_format.md`「生成顺序」一致：核心看点提炼自正文，编者按又要基于正文与核心看点）。
4. **最后**才做：5 个标题 + 摘要钩子 + 封面 Recraft Prompt。

> 与逐字稿唯一区别：非正文多了"封面 Prompt"，且这三件都放最后。删某节时检查它是否是后文铺垫，若是，把后文依赖它的句子改成不依赖前文的版本。
> **借 takeaways 校准**：标题（5 选）与编者按，可借嘉宾 / 主持人上节目后自发的 takeaways（如总结推文）反向校准，并捞回正文遗漏的高光素材。

## 外部素材处理（字幕之外的资料）

素材不限于视频字幕，还包括**推特 / 文章 / 官方发布页 / 他人解读 / 嘉宾其他演讲**。

| 素材类型 | 可以怎么用作补充 |
|---|---|
| 视频字幕（主源）| 重构正文的事实基底 |
| 嘉宾 / 主持人自己的总结贴 | 校准标题 / 价值概括 / 核心观点；捞回遗漏的高光素材 |
| 官方发布页 / 新闻 | 给文中提到的产品 / 数据补一句事实，**标明来源** |
| 第三方解读（视频 / 文章）| 仅作背景佐证 / 配图来源，标明"第三方"，勿当官方口径 |
| 嘉宾其他演讲（如 Keynote）| **幻灯片 / 图表走「媒体占位」配在对应章节** |

图文精读是"重构叙事"、不是逐字还原，所以**外部事实可以写进重构正文，但必须**：① 标明来源；② 与"嘉宾观点 / 字幕内容"区分清楚，不混为一谈、不假托成嘉宾原话；③ 无据标 `⚠️建议人工核对`、不臆造；④ 第三方来源显式标明。幻灯片 / 图表照旧走「媒体占位」。

**例外与铁律**：若要把**嘉宾在别的对谈里的发言**并进本篇、且不再区分来源（读者分辨不出是别处说的），**必须走 `skills/dialogue_transcript.md` 的「候选池核实 → A/B 双 Agent 并入协议」**，模式 A 与模式 B 共用同一套闸门，不得因为"图文精读本来就是重构"而跳过。该协议同时规定了用户推翻 Agent A 裁决时的补偿动作。
