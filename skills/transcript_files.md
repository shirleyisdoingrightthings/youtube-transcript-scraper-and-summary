# 字幕文件命名与存放规范（Transcript Files）

> **调用时机**：用户**一次发来多条链接**做批量预判时（CLAUDE.md 阶段 -1）；或要从 `transcripts_pending/` 取用、移动待用字幕时（Step 1 复用 / Step 3 归档）。
> **来源**：2026-09-16 从 CLAUDE.md 阶段 -1「批量命名规则」原样拆出，规则本身未改。

---

## 批量命名规则（多条链接时强制）

用户**一次发来多条链接**要求批量预判时，**禁止**让多个视频共用同一个 `transcript_temp.json`（会互相覆盖、导致后抓的冲掉先抓的）。命名分三段走：

1. **抓取阶段**：一律输出为 `transcript_temp_<video_id>.json`（如 `transcript_temp_9fubhllmsBU.json`），一个视频一个文件，可并行抓取。
2. **预判交付后（无论用户是否已选定）**：把**这一批全部文件**（选定的 + 暂未选定的）都按 **YouTube 视频原标题**重命名（`<视频原标题>.json`，路径非法字符 `/ : |` 替换为 `-` 或空格，不用下划线），便于用户肉眼区分。**`transcript_temp_<video_id>.json` 只是抓取阶段的临时命名，预判一交付就必须重命名掉，不得以 temp 文件名滞留在项目根目录**（哪怕用户还没拍板选哪几条）——JSON 本身的 `url` 字段（脚本输出的第二个字段，已在文件开头）就是该视频链接的记录位置，无需额外补充。
3. **未选用的一律移入 `transcripts_pending/`**（没有则新建，重命名后再移动），**默认不删除**——暂缓 ≠ 作废，重抓要花钱且可能已失效。项目根目录只放脚本与文档，不留散落的字幕文件。
   - **用户明确说删就直接删**，不必二次确认、不必论证，执行日志一句话带过即可（例：「其余三份经用户指令删除」）。默认不删只约束**你自己**的判断。
   - **留存待用的字幕必须配一份 summary 导读**，与 JSON 同目录同名、后缀 `.summary.md`（如 `<视频原标题>.summary.md`）。内容固定四块：① 基本信息表（video_id / URL / 场合 / 时长与覆盖率 / 抓取日期 / 预判分 / 当前状态与暂缓理由）；② 这期在讲什么（一句话定性 + 形态说明）；③ **章节地图**（时间戳 → 内容，覆盖全片）；④ **Highlight**（可直接做钩子的金句 / 猛料，带时间戳）+ **开工前必须处理的核对项**（已知的字幕听写错误、需查证的外部事实）。目的是让日后接手的 Agent **不必重读全片字幕**就能判断要不要做、从哪下手。
4. **进 Step 3 归档时**：把本次要做的那份从 `transcripts_pending/`（或根目录）移进 `output/<标题>/`，按既有规则改名为 `transcript.json`（单源）或 `transcript_<来源>.json`（合辑 / 多来源稿）。

> **开工前防呆**：`transcripts_pending/` 里的文件名已被重命名过，**务必按 JSON 的 `video_id` 字段确认拿到的是本次要做的那条，不要凭文件名猜**。
> **交接文档联动**：若某篇稿子的交接文档里引用了待用字幕的存放位置，移动文件后必须同步更新该交接文档（呼应 CLAUDE.md Step 4.5 的交接文档同步铁律），否则接手的新 Agent 会找不到、甚至重抓一遍。
